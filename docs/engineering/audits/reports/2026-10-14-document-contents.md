# Document contents: implementation and stabilization audit

Date: 2026-10-14. Scope: optional manuscript contents for PDF, Word and Markdown. User requirement: searchable PDF text, clickable contents and navigation bookmarks, with chapters and parts/acts. Tagged PDF/PDF-UA was not requested.

## Cleanup summary

The export modal exposes **Contents** and **Heading levels** for every manuscript source and all three document formats. The existing Markdown scene indexes retain their separate meanings. No TOC defaults were retroactively enabled. The duplicate inner TOC heading was removed; the new controls use existing ERT primitives without new CSS or keyboard commands.

Assembly owns book hierarchy; Pandoc owns PDF pagination and the Word TOC field. A small publishing helper owns depth normalization, Markdown destinations and the PDF navigation header. Layout macros flush queued navigation after their physical page break, placing destinations on opener pages rather than on the preceding page. The flush is empty when document contents are disabled.

## Findings, highest priority first

No release-blocking or high-priority defect was found in the changed feature during stabilization review.

* **Medium, pre-existing repository check failure:** the additional standalone `node scripts/fallback-gate.mjs` fails its `or-chain-3` baseline: 79 occurrences against 52. Comparing the scanner's rule on each changed production file against `HEAD` showed 12 before and 12 after; the repository had 79 before this feature as well. This implementation contributes zero to that failing rule. The baseline was not changed, and unrelated source files were not rewritten. All 14 standard `npm run gates` checks pass; this extra check is reported separately.
* **Validation limitation:** the real Word package contains the TOC field, depth range and Heading1–Heading3 styles, but final pagination and field updating were not inspected in Microsoft Word. The modal and wiki explicitly instruct the author to update the entire table in Word.
* **Environment limitation:** Contemporary Literary's normal Source Serif 4 font is unavailable to XeLaTeX on this Mac. Its real navigation test uses a cloned specification with the available system serif font. No production specification, font selection or OS font installation was changed. Standard Manuscript, Signature Literary and Modern Classic rendered with their configured fonts.
* **Compatibility boundary:** a custom PDF template using custom opener macros must include the navigation hook. An older template is rejected with a specific regeneration/reinstallation message. Managed bundled layouts are regenerated by the existing installer. Heading-only templates do not require that hook.

## Refactors performed and dead code removed

No architectural refactors. The redundant TOC subheading was removed. The existing hidden legacy TOC behavior is retained, rather than reinterpreting an author's old scene index as a document TOC. Stabilization review was read-only; it did not introduce speculative fixes or change unrelated repository findings.

## Behavior confirmed

* Radial Timeline books use explicit Part boundaries, resolved Chapter markers and scene headings. An authored `Part: Act II` keeps the Act II label in contents. The analytical `Act` field is not a publishing boundary.
* Folder and single-file sources use existing headings without adding source YAML. The exported Markdown adds unique block IDs plus matching HTML anchors; two identically titled headings navigate separately inside Obsidian. Existing block IDs are preserved unless duplicated across compiled notes.
* PDF contents include page numbers, GoTo annotations and nested bookmarks. Anchors land on the actual opener pages, including layouts that omit visible part/chapter pages.
* A requested contents with no eligible headings fails instead of silently publishing an empty table. Contents for split output are built from that file's included material.
* Contents mode and depth survive format switches and saved presets. Changes invalidate existing proofs.
* The existing automatic delivery checks, Open file action and recent-export receipts remain available.
