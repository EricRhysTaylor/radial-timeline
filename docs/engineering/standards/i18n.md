# Strings and Translations

Radial Timeline ships English and eight other languages (`SUPPORTED_LOCALES` in
`src/i18n/index.ts`). English is the source of truth; every other language
falls back to English, key by key, wherever it has no translation of its own.

## English first until features settle

Owner's decision, 2026-11-07: "we need to only build out in english until
features are settle."

- **New strings go into `src/i18n/locales/en.ts` only.** Do not add them to the
  other locale files. A writer using another language sees the English string
  until the translation pass.
- **A changed meaning removes the translation.** When an English string's
  meaning changes, delete that key from every other locale. The language then
  shows the new English text rather than a translation that says something
  else. A fix to spelling or punctuation that keeps the meaning keeps the
  translations.
- **A removed key leaves every locale.** Delete it from all nine files.
- **One translation pass before a major release.** Before 8.0, the languages
  are brought back to full coverage in one pass, checked against the core-term
  glossary (`src/i18n/locales/glossary.test.ts`).
- **Keep every existing language.** Do not remove a locale.

## What the checks enforce

- `npm run release:i18n` (`scripts/check-i18n-release.mjs`) reports each
  language's coverage and how many strings it shows in English. It fails when a
  locale has a key English no longer has (a stale translation), when the locale
  files and `SUPPORTED_LOCALES` disagree, and when a language is missing from
  the release bundle.
- `npm run i18n:coverage` lists the English-only keys per language
  (`--verbose`).
- `src/i18n/locales/translations.test.ts` checks every translated key: the same
  placeholders as English, no empty or token-polluted text, protected author
  syntax kept verbatim, and no keys English no longer has.
- `src/i18n/locales/thirdPartyNames.test.ts` keeps third-party plugin names out
  of every locale.
